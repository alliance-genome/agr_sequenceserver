# What changed in October 2026, and what it cost to find

Twenty-six pull requests across three repositories, 2026-10-08 to 2026-10-16.
Eighteen in `agr_sequenceserver` (#41 to #58), seven in
`agr_blast_service_configuration` (#62 to #68), one in `agr_blastdb_manager`
(#79). Net 2,201 insertions against 6,401 deletions here, 168 against 35 in
the config repo and 441 against 6 in the manager, so most of it was removing
things that did not work.

This file is the arc. The detail lives where it belongs: deployment procedure in
`DEPLOYMENT.md`, the Alliance-wide work in `ALLIANCE_WIDE_PLAN.md`, the system
in `ARCHITECTURE.md`, the audit that started it in `AUDIT_2026-10.md`.

## The defects, and how each was found

Nine were found by measuring something that had been asserted rather than
checked. That is the pattern worth taking from this.

**Four request-handling defects** where request input became a filesystem path,
live on production for a month. A submitted `id=../../../../tmp/x` wrote a job,
query included, anywhere the process could reach, as root in the container
(#31, before this window).

**`init_database` was dead code for a year.** `6e969b2c` removed the call and
the method; an upstream merge brought the body back without the call, and it
could not have run anyway, since the body called a `makeblastdb` reader this
fork had moved. Restoring it fixed 27 of the 41 non-browser spec failures,
because validating `database_dir` is the half that is not optional (#42).

**`routes.rb` hardcoded a container path in five places.** `/db` as the
database root in `database_dir_for`, in `/blast/:mod/` and in the alias route;
`/sequenceserver` twice for `environment.json` and `environment_info.json`.
Each silently degraded rather than failed: the config readers fell back to an
empty config, so every hit lost its genome browser and MOD gene links, and an
empty config is also what a release with no `environment.json` legitimately
has (#43, #51, #52). All five read the config now. The fifth and the two `/db`
ones were only found while checking this file's own claim that none were left,
which had been written on the strength of a grep for one of the two spellings.

**BLAST conflates sequences sharing an id across databases of one search.**
Four of the nine Alliance genomes name their chromosomes 1..n. Before
prefixing, a cross-species search returned 23 of 36 colliding pairs on
ALLIANCE and 6 on WB WS298; after, 0 and 0. Mouse went from 0 hits to 20, rat
from 0 to 21, and human from 74 to 29, which revealed misattribution rather
than absence (#39, #61, before this window).

**The genome browser links were wrong in three ways at once.** The Alliance rat
directory is named `RGD_mRatBN7_2`, so `database_path.include?("RGD")` was true
and the RGD rule answered `Chr1` where the browser wanted `1`. The Alliance
yeast assembly is `Saccharomyces_cerevisiae`, verbatim what the SGD rule
matches. And for the 680 human and 39 mouse sequences that carry a defline, the
generic fallback took its first word: `Homo`, `Mus` (#43, #46).

**Four of nine Alliance genomes were on a different assembly than JBrowse 2
serves.** Rat and zebrafish were the dangerous pair: every chromosome name
matched, so a link would build and open, on coordinates from another assembly.
Rat chromosome 1 is 260,522,016 bases in the old BLAST database and 270,518,180
in JBrowse 2. All four were rebuilt on the assembly JBrowse 2 loads, so the
coordinates now agree by construction (#63).

**WormBase binds five C. elegans databases to one filename.** All five are
stored as `c_elegansdb`, so a CB4856 hit was handed N2's browser and N2's
`seqid_prefix`, which stripped nothing from `CB4856_II`. Simulating
`extract_ref_name` over all 128,018 WS298 nucleotide sequences found 3,157 that
no browser could resolve: 2,062 collapsed to `I`, because four assemblies carry
the defline `1 <length>`, and 1,095 kept `gb|CM008509.1|` notation (#46, #64).

**The documented production redeploy would have deleted the job history.** It
opened with `docker rm -f`, and the jobs lived in the container's writable
layer. 1,841 result URLs, 3.6 GB, by the time the release ran (#41, #48).

**`spec/dotdir` had collected 145 job directories.** The cleanup hook was
scoped `type: :feature` while the specs creating jobs are not feature specs,
and `spec/dotdir/*` is gitignored, so it accumulated invisibly (#50).

## Four things that were asserted and turned out false

Worth recording because each was in a document or a comment, stated plainly,
and wrong.

* `spec/blast_versions` was called inert, with no file named `*_spec.rb`. Each
  of its ten release directories holds one, they are collected, and they supply
  214 of the suite's 376 examples. The measurement that suggested otherwise
  passed `--exclude-pattern "blast_versions/**"`, which matches nothing from
  the default path, so both runs were the same number (#49).
* The plan said the Xenopus vocabularies are `Chr1L`/`Chr1S` and
  `Chr1`..`Chr10`. That was right for the assemblies JBrowse 2 serves and wrong
  for the scaffold-level builds then being searched, which had 108,033 and
  6,822 scaffolds (#63, #44).
* The plan worried that fly would not resolve from a RefSeq-derived name.
  It resolves 8 of 8: the Alliance fly database already carries FlyBase arm
  names, which are the `.fai` names verbatim (#44).
* `DEPLOYMENT.md` said production was seven pull requests behind, then fifteen.
  The git range was the only number worth trusting, and it was 22 by the time
  the release ran (#42, #48).

## How the Alliance deployment is named now

`/blast/ALLIANCE/9.1.0/`, by Alliance release, and it gets a release whenever
the Alliance does: a new config file, a new environment in `global.yaml`, a new
directory. A clean rename, no alias, so `/blast/ALLIANCE/prod/` answers 404.
`/blast/ALLIANCE/` redirects to 9.1.0 without new code, because the `:mod`
route already picks the highest numeric version (#66, #51).

## Phase 3, 2026-10-15 and 2026-10-16

Four steps, five pull requests, and one of the four premises had expired.

**The tree can be searched in English** (#56). 40 common names over 129
patterns, every pattern matching one of the 910 labels this host serves. The
search filters rather than tints, and a query matching nothing hides the tree
and says so instead of showing all of it, which is what jstree does when
nothing matched.

**A cross-species result can be read one organism at a time** (#58). Each
organism in the summary is a switch that hides its hits and its alignment
blocks. The rows are selected through a `data-organism` attribute and one CSS
rule per hidden organism, because `hits.js` renders in 25ms batches and holds
the created elements in its own state, so a prop added to `Hits` never reaches
a hit already on the page.

**The Alliance deployment is published** (#57, config #68). The header logo
linked `alliancegenome.org/members/ALLIANCE`, a member page for something that
is not a member, on every page it serves; `environment_info.json` did not list
the deployment at all; and `metadata.public` was `false`. All three fixed, and
the smoke suite now asserts the manifest entry, which is the only thing that
will notice if it goes missing from a file that lives in no repository.

**A partial build can no longer publish** (manager #79). `copy_config_file`
republishes the build input as `environment.json` and ran whenever one entry
succeeded, which is how nine genomes came to be declared while one was served.
Free space is checked before anything is downloaded, with factors measured
rather than guessed: 3.06x and 3.05x for `gunzip` of two genomic FASTAs, 0.78x
for built databases against their summed sources.

**Step 11's premise had expired.** It was written when a nine-genome `tblastn`
for human ACTB returned 131 hits with no mouse and no rat. The same query now
returns 124 hits from all nine organisms, the largest holding 23%. That was id
conflation rather than ranking, and the `seqid_prefix` rebuild fixed it, so
the switches are a convenience and not a repair. A comment in
`alliance_species.spec.js` still said mouse was crowded out; it was true when
written and is corrected.

Two plan items were deliberately not built, both recorded in the pull
requests. Grouping the hit list by organism needs a rewrite of the batched
renderer that keeps a 10,000-HSP page responsive. `[Select all]` for a
single-database category stays hidden, because selecting all of one database is
the checkbox beside it.

## What is still open

* **Nobody owns the ALLIANCE config.** Two commits, both 2024-03-21. Per-MOD
  configs have release-cadence refresh wired into the Makefile; this one needs
  an owner and a cadence, and it is the one Step 13 item code cannot close.
* **Nothing compares what is served against what is declared.** The new gate
  stops a partial build publishing a manifest, but a manifest an earlier
  partial build published stays wrong until someone rebuilds. That is the check
  that would have found the 2024 failure.
* **`report.spec.js` fails on node 18** and passes on CI's node 22, so a local
  `npm test` shows one failure that CI does not.
* **The SGD fungal deployment cannot be named in `global.yaml`.** Its configs
  are `databases.SGD_fungal.*.json`, and the provider token must be a directory
  under `conf/`. It needs `-j <file>`.
* **`WB/dev`** is 61 databases from January 2024 with no config in this repo,
  reachable at `/blast/WB/dev/` though excluded from the `/blast/WB/` redirect.
* **Production cannot be viewed over plain HTTP.** `HTTPS=on` makes it emit
  absolute `https://` asset URLs, and nothing serves TLS on 4568, so the page
  returns 200 and loads no CSS or JavaScript. The test instance on 4570 runs
  the same image and config without that variable and renders.
* **MOD data defects**, unchanged and not ours to fix: ZFIN's "TALEN Sequences"
  holds morpholinos, ZFIN ships no protein databases, three ZFIN URIs 404, and
  FlyBase's `genome_browser.data_url` prefix does not exist.

## The method, since it is the transferable part

Every number in this file came from running something. The habits that found
the defects above:

* **Compare against the thing itself.** The genome browser links were checked
  by fetching each assembly's `.fai` from the browser and asserting every
  refName appears in it. That is what caught `Chr1` for GRCr8, and `Homo` for a
  human scaffold.
* **An HTTP 200 is not a working page.** Nine of the Alliance checks went
  through the JSON API and never loaded a page, which is how a broken example
  and a four-level tree passed as finished. The failure mode is specific and
  documented: an `HTTPS=on` container over plain HTTP returns valid HTML and
  loads nothing.
* **Diff before and after on the same query.** Every link change was verified
  by running one query against the old build and the new and diffing the URLs,
  which is how WB, FB, SGD and RGD were shown byte-identical while ALLIANCE
  changed.
* **Simulate across the whole corpus, not a sample.** 128,018 WS298 refNames
  and 967,185 ids were checked offline, which found 3,157 broken links and 0
  collisions respectively. A sample would have missed the four databases where
  every sequence collapses to `I`.
* **Re-measure the premise before building the fix.** Step 11 was three days'
  work against a problem that two earlier pull requests had already removed.
  One query through the JSON API, five minutes of machine time, said so.
* **Measure the constant instead of choosing it.** The disk check needed two
  expansion factors. `gunzip` on the two smallest sources and `du` on the built
  tree gave 3.05x and 0.78x in under a minute, which is a number that can be
  defended in a review; "assume 4x" is not.
